# Mayor Simulator 視覺渲染重做需求

## 主題：從文字格子改為真正的遊戲地圖、建築物、地形與 NPC 互動

---

## 一、問題說明

目前 Godot 版本雖然已經加入了：

* 8 × 8 地圖
* 建築分類
* 建築顏色
* NPC 標籤
* 外觀切換
* 城市背景風格選項

但目前畫面仍然是：

* 平面格子
* 色塊
* 文字標籤
* 類似資料表或管理面板

這不符合目前的遊戲視覺目標。

目前做法只是「格子 UI 美化」，不是「真正遊戲渲染」。

---

# 二、本次真正目標

請將中央城市地圖從目前的文字格子，改造成真正的遊戲畫面。

## 核心要求

> 底層可以繼續保留格子邏輯，
> 但玩家看到的畫面不能再是純方格、純文字、純色塊。

玩家應該看到：

* 真正的建築物外觀
* 地形
* 草地
* 道路
* 樹木
* NPC
* 城市環境
* 建築動畫
* 可以互動的城市物件

---

# 三、重要方向說明

玩家希望的視覺方向類似城市建造遊戲畫面。

可以參考以下視覺特徵，但不要複製任何受版權保護的素材或介面：

* 城市地圖不是純格子
* 建築物有實際外觀
* 能看到道路、地形、區塊、環境
* NPC 或車輛能在地圖中活動
* 地圖本身像一個可玩的城市場景
* UI 面板只是輔助，不應該取代遊戲畫面

本作預設風格不是寫實都市，而是：

# 可愛童話城堡風城市模擬遊戲

---

# 四、請不要再做的事情

本次請明確避免以下錯誤方向：

* 不要只把方格換顏色
* 不要只在格子上寫建築名稱
* 不要只把格子改成圓角
* 不要只加背景標籤
* 不要用「文字」當建築主要呈現
* 不要讓 NPC 只是貼在格子上的小標籤
* 不要讓地圖看起來像表格或 UI 清單
* 不要把這次任務理解成一般 UI 美化

---

# 五、正確架構：邏輯層與視覺層分離

請把城市地圖分成兩層：

## 1. 邏輯層

邏輯層可以繼續使用目前的格子系統。

它負責：

* 地圖座標
* 建築資料
* 建築類型
* 建築效果
* 財政計算
* 月度結算
* 人口與滿意度
* 法案與政策影響

### 重點

邏輯層可以維持 8 × 8 格子，不一定要重寫。

---

## 2. 視覺層

視覺層是玩家真正看到的畫面。

它負責：

* 地形貼圖
* 建築 Sprite
* 道路 Sprite
* 樹木與裝飾物
* NPC Sprite
* 動畫
* 點擊互動
* 建築資訊彈窗

### 重點

玩家看到的應該是視覺層，不是邏輯格子本身。

---

# 六、建議實作方向

## 1. 使用 2D / 2.5D 城市視角

本次不需要做大型 3D 城市。

請優先採用：

* 2D 俯視角
* 或 2.5D 斜角視角
* 或等角視角風格

### 建議優先順序

| 方案        | 建議程度 | 說明              |
| --------- | ---: | --------------- |
| 2.5D 等角視角 |   最高 | 最像城市建造遊戲，建築辨識度高 |
| 2D 俯視角    |  可接受 | 較容易實作，但要有建築圖像   |
| 3D 寫實城市   | 暫不建議 | 成本太高，不適合目前 MVP  |

---

## 2. 地圖底層改成 TileMap 或等效渲染層

請建立真正的地圖底層。

### 地形至少需要包含

| 地形   | 視覺方向           |
| ---- | -------------- |
| 草地   | 童話小鎮草地         |
| 石磚道路 | 城堡城鎮道路         |
| 花草地  | 裝飾用地形          |
| 廣場地面 | 市政府、商場、捷運附近使用  |
| 工業地面 | 工廠、發電廠、瓦斯場附近使用 |

### 視覺要求

* 空地不能只是寫著「可建造」的方格
* 空地應該看起來像草地或待開發地
* 地形需要有基本紋理或圖案
* 地圖可以保留格子對齊，但格線不應是主視覺

---

# 七、建築物視覺需求

## 1. 每個建築要有實際外觀

目前每個建築只是一個色塊加文字，這次要改為真正建築圖像。

### 每個建築至少需要

* 建築 Sprite 或可視化物件
* 建築名稱可作為 tooltip 或小標籤，不應作為主要本體
* 建築點擊後可開啟資訊面板
* 建築外觀要能一眼分辨類型

---

## 2. 第一批必須可視化的建築

請優先為以下建築建立外觀。

| 建築    | 視覺方向            |
| ----- | --------------- |
| 住宅    | 可愛小屋、藍色屋頂、煙囪、花窗 |
| 社會住宅  | 較大的溫馨住宅群        |
| 商店    | 可愛店面、招牌、櫥窗      |
| 大型商場  | 童話風商業館、較大建築     |
| 工廠    | 童話工坊，有煙囪但不要太陰沉  |
| 公園    | 樹木、花圃、長椅、噴泉     |
| 學校    | 小鐘樓、學院感         |
| 圖書館   | 石造館舍、書卷感        |
| 醫院    | 白色建築、紅十字、柔和外觀   |
| 警局    | 深藍色秩序建築         |
| 消防局   | 紅色救援站           |
| 公車站   | 站牌與候車亭          |
| 捷運站   | 地下入口、藍色交通標誌     |
| 停車場   | 停車格與 P 標誌       |
| 發電廠   | 工業設施、煙囪或能源塔     |
| 自來水廠  | 水塔、水池或藍色設施      |
| 垃圾處理場 | 乾淨化處理廠，不要過度噁心   |
| 瓦斯場   | 儲氣罐或能源設施        |
| 機場    | 小航站樓與短跑道感       |
| 體育館   | 圓頂建築或競技場        |
| 市政府   | 城堡式行政廳或小王宮      |

---

## 3. 如果暫時沒有正式美術素材

若目前沒有正式素材，可以先使用以下方式：

### 可接受

* Godot 內建繪圖節點組合成簡易建築
* 程式化繪製簡單建築圖案
* 使用簡單 Sprite placeholder
* 使用幾何形狀組合成童話建築
* 使用自製低精度 2D 圖示

### 不可接受

* 只用純色方塊
* 只用文字表示建築
* 只把原本格子換顏色
* 只在格子上寫「住宅」「商店」「工廠」

---

# 八、地圖互動方式

## 1. 建造流程要保持

目前的建造流程要保留：

```text
選擇建築 → 點擊地圖空地 → 扣除資金 → 放置建築 → 更新數據
```

但視覺上要改成：

```text
選擇建築 → 點擊草地或空地 → 播放建造動畫 → 出現建築物 → 更新城市狀態
```

---

## 2. 點擊建築

點擊已建造建築時，應顯示建築資訊面板。

### 建築資訊面板至少包含

* 建築名稱
* 建築類型
* 建造成本
* 維護費
* 對城市數值的影響
* 外觀設定按鈕
* 若未來支援，可加入拆除或升級，但本次不是必要

---

## 3. 地圖上保留清楚回饋

需要有：

* 可建造地塊提示
* 滑鼠 hover 高亮
* 建造成功動畫
* 資金不足提示
* 選中建築提示
* 建築點擊回饋

---

# 九、NPC 視覺與互動

## 1. NPC 不能只是文字標籤

目前 NPC 若只是顯示「居民」「工人」「商人」的標籤，仍然不符合目標。

請改成：

* NPC 有可見角色圖像
* NPC 能在地圖上移動
* NPC 有簡單動畫
* NPC 可被點擊
* 點擊後出現對話氣泡或對話框

---

## 2. NPC 類型

請先做以下 NPC 類型。

| NPC  | 視覺方向          |
| ---- | ------------- |
| 一般居民 | 可愛市民          |
| 學生   | 書包或制服元素       |
| 商人   | 店員或商務造型       |
| 老年居民 | 溫和長者          |
| 工人   | 工帽或工作服        |
| 公務人員 | 簡單正式服裝        |
| 議員   | 市議會角色，可用於法案系統 |

---

## 3. NPC 行為

第一版 NPC 行為不用複雜，但要有生命感。

### 至少需要

* NPC 在地圖上隨機走動
* NPC 不要全部卡在同一點
* NPC 可以在建築附近停留
* NPC 點擊後出現對話
* NPC 對話根據城市狀態變化

---

## 4. NPC 對話與城市狀態連動

NPC 對話不可完全隨機，應與城市狀態有關。

### 範例

| 狀態      | NPC 可能說               |
| ------- | --------------------- |
| 稅負太高    | 「最近生活開銷好重，希望市長能調整一下。」 |
| 公共事業費太高 | 「水電瓦斯費加起來真的有點吃不消。」    |
| 交通良好    | 「最近出門變方便多了！」          |
| 工廠太多    | 「工作機會變多了，但空氣好像變差了。」   |
| 公園多     | 「這座城市很適合散步呢。」         |
| 治安低     | 「晚上出門有點不安心。」          |
| 法案通過    | 「聽說新的政策要開始執行了，希望會更好。」 |
| 滿意度高    | 「我很喜歡住在這座城市！」         |
| 滿意度低    | 「最近大家好像對市政有不少怨言。」     |

---

# 十、建築外觀客製化

## 1. 目前外觀切換不能只是文字狀態

如果目前已有「外觀：某某風格」文字，請改為真正影響建築視覺。

玩家切換外觀後，地圖上的建築外觀要真的改變。

---

## 2. 支援自訂項目

第一版先支援以下自訂：

| 項目   | 說明           |
| ---- | ------------ |
| 屋頂顏色 | 改變建築屋頂色      |
| 牆面顏色 | 改變建築牆面色      |
| 裝飾樣式 | 花草、旗幟、窗框     |
| 建築變體 | 同一建築 2～3 種造型 |

---

## 3. 優先支援建築

先支援：

* 住宅
* 社會住宅
* 商店
* 大型商場
* 學校
* 市政府
* 公園

不需要一開始所有建築都支援完整客製化。

---

# 十一、動畫需求

## 1. 建築建造動畫

放置建築時，加入：

* 淡入
* 縮放彈出
* 小型粒子或光點
* 建造完成提示

## 2. NPC 動畫

NPC 至少要有：

* 移動動畫
* 待機動畫
* 點擊時出現對話氣泡

## 3. 環境動畫

可加入：

* 雲朵移動
* 樹木微動
* 旗幟飄動
* 噴泉動畫
* 煙囪煙霧

## 4. UI 動畫

可加入：

* 面板滑入
* 公告彈窗
* 按鈕 hover
* 月度報告顯示動畫

---

# 十二、UI 與遊戲畫面關係

目前 UI 佔據太多視覺注意力，城市本體不夠突出。

## 請調整方向

* 中央地圖應是主角
* 左側與右側面板應是輔助
* UI 不應壓過城市場景
* 建築資訊可用彈窗或側邊資訊卡
* 玩家主要目光應集中在城市地圖本身

---

這次不要一次把所有美術系統做爆，請分階段。

---

---

## 第三階段：NPC 實體

完成：

* NPC 圖像

---

## 第四階段：動畫與互動 polish

* 建造動畫
* 環境動畫

---

## 第五階段：建築客製化

完成：

* 點擊建築

---

# 十四、驗收標準

完成後必須符合以下標準：

## 地圖

* 中央地圖不再像表格
* 空地看起來像地形
* 有草地、道路、環境元素
* 格子邏輯可以保留，但視覺上不是一堆方塊

## 建築

* 建築不是色塊
* 建築有實際外觀
* 建築名稱不再是主要辨識方式
* 玩家能透過外觀辨識建築類型

## NPC

* NPC 不是文字標籤
* NPC 有角色圖像
* NPC 會移動
* NPC 可互動
* NPC 會說話

## 動畫

* 建造有動畫
* NPC 有動態
* 地圖有生命感
* UI 有基本互動回饋

## 客製化

* 外觀切換會真的改變建築樣貌
* 不是只改文字說明

本次不是「把格子 UI 做漂亮」。

本次真正目標是：

> 把中央城市區域改造成玩家看得見建築、看得見居民、看得見地形、能互動、能感受到城市生命感的遊戲畫面。
