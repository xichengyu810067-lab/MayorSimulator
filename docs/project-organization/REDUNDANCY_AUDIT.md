# 遊戲功能、數據與人物冗餘稽核

稽核日期：2026-07-22  
範圍：目前可執行遊戲、主程式內可達功能、正式資料庫與畫面呈現。歷史截圖、測試輸出與備份不會載入遊戲，故列為開發佐證，不視為遊戲內容重複。

## 判定原則

- 同一功能只能有一個主要控制入口。
- 同一資料只能有一個可寫入的正式來源；其他畫面只能讀取或建立衍生摘要。
- HUD 可保留即時摘要，明細頁必須提供不同層級的分析，不能原樣複製。
- 地圖人物可以使用視覺代理，但代理必須引用正式人物 ID，不得建立第二份人物資料。
- 不同機關中的不同職務不算重複；同一人不得以無關 ID 重複出現在不同名單。

## 功能唯一責任

| 功能區 | 唯一責任 | 保留內容 | 禁止出現 |
|---|---|---|---|
| 頂部 HUD | 即時城市摘要 | 日期、資金、人口、滿意、民怨、信任、評分、城市等級 | 明細控制、人物請求全文 |
| 城市數據 | 分析明細 | 五項城市服務、四群體滿意、收入來源與淨收支 | 稅費拉桿、請求處理 |
| 稅率與公共事業費 | 財政控制 | 14 項分類控制、預期變化、運作預警 | 城市服務評分、人物與司法資料 |
| 民情中心 | 居民陳情處理 | 自動彙整所有有效 NPC 陳情、請求全文、處理狀態、接受請求 | 民怨與信任量表、城市數據 |
| 月度報告 | 歷史結算紀錄 | 當月收支變化、人口變化、滿意變化、公告 | 當前 HUD KPI 卡 |
| 選擇建築 | 新建建築選擇 | 分類選擇、藍圖捷徑、建築效果 | 民意、司法、既有建築控制 |
| 地圖建築情境面板 | 既有建築控制 | 點擊建築後顯示樣式、屋頂、外觀、維護、拆除 | 第二個樣式／維護／拆除入口 |
| 設計藍圖 | 建築設計與送審 | 建材、規模、樓層、裝飾、工人 | 民意、滿意、司法資料 |
| 政策與法案 | 治理與議會 | 政策、法案標籤、未實施／審核中／已實施 | 委員名冊、法院案件、居民請求 |
| 法院審判 | 違法行政案件辯護 | 案件、證據、判決風險、三種辯護 | 委員資料庫、監察彈劾 |
| 監察質詢 | 行政調查與彈劾答辯 | 質詢案件、指控、三種答辯 | 司法判決、委員資料庫 |
| 地圖居民對話 | 日常回饋與導引 | 情境對話、是否有待辦陳情 | 民情中心請求全文 |

## 正式資料來源

| 資料 | 唯一來源 | 顯示／代理規則 |
|---|---|---|
| 建築 | `data/catalogs/buildings.gd` | 選擇頁與地圖只讀取同一建築定義 |
| 政策 | `data/catalogs/policies.gd` | 政策卡直接讀取正式目錄 |
| 法案 | `GovernanceSystem.bill_definitions` | 主畫面動態建立法案卡，不再保存第二份法案表 |
| 議會投票人物 | `data/databases/governance/lower-council/councilors.json` | 固定 30 位，下議院模型直接讀取 |
| 司法／監察委員 | `data/databases/governance/justice-oversight/committee_members.json` | 15 位司法委員與 10 位監察委員共用機關名冊，但職務、席次、任期分開 |
| 一般居民 | `PopulationSystem.records` | 正式保存 300 人；地圖只建立 24 個引用 `record_id` 的視覺代理 |
| 治理狀態 | `GovernanceSystem` | 待審法案、生效法案、否決紀錄、案件與民怨／信任均由同一系統持有 |

## 已清除的重複

1. 民情中心移除民怨與市政信任量表，改為自動列出全部有效 NPC 陳情與其處理狀態。
2. 月度報告移除淨額、人口、滿意與評分四張即時 KPI 卡。
3. 樣式、屋頂、外觀、維護、拆除全部移到點擊建築才出現的單一情境面板；建築選擇頁與全域快捷列不再重複控制。
4. 地圖居民對話不再複製請求全文，只提示玩家前往民情中心。
5. 移除主程式舊有 7 人議會名單、重複法案表與平行立法狀態；統一使用正式 30 人模型。
6. 移除未被目前遊戲載入的舊頂欄、左右側欄、舊報告列與其相依輔助函式。
7. 人物稽核以永久 `npc_id` 與完整人物資料為準；保留既有 300 人的姓名、年齡、工作與收入，不把同名但資料不同的居民誤判成同一人。
8. 移除玩家手動跳日／跳月入口；遊戲時間以現實 120 秒自動前進一日，視窗失去焦點與確認離開時暫停，存檔不保存作業系統時間戳，因此不會離線補算。

## 自動化防回歸

`tests/integration/redundancy_audit_test.gd` 會檢查：

- 民情中心沒有民怨／信任文字與量表。
- 月報沒有即時 KPI 量表。
- 拆除只有一個控制入口。
- 建築情境面板固定只有樣式、屋頂、外觀、維護、拆除五項。
- 民情中心卡片數量與全部有效 NPC 陳情一對一，且可以直接受理。
- 第 120 秒才換日；暫停期間與離線期間不產生時間進度。
- ActionDock 語意動作沒有重名。
- 主程式沒有平行法案資料庫、7 人議會或平行立法狀態。
- 稅、公共事業費、服務費的識別碼互不重疊。
- 8 項法案 UI 與正式定義一對一。
- 300 位居民 ID 與完整人物資料不重複；24 個地圖代理各自引用正式居民。
- 30 位議員與 25 位司法／監察委員的 ID、姓名在正式官員名冊中唯一。
