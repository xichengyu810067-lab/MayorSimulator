# 遊戲數據視覺化 UI 實作與驗證報告

## 目標

在不遮擋主要地圖與不移除精確數字的前提下，將原本偏文字式的資料改成可快速掃讀的圖示、方向符號、狀態色與進度條。驗證固定使用邏輯解析度 1280 × 800、實體截圖 2880 × 1800。

## 修改前觀察

| 畫面 | 主要問題 |
| --- | --- |
| 主畫面 | 頂部數值只有文字；玩家必須逐欄閱讀，無法從形狀與色彩快速判讀。 |
| 城市數據 | 城市服務已有基本長條，但缺少一致的狀態文字與色彩；財政資料仍以文字為主。 |
| 財政 | 滑桿與說明段落較長，建議區間、收入方向與設施缺口不易一眼區分。 |
| 建築／政策 | 卡片用句子描述效果，人口、滿意度、環境、交通與支出方向需逐字閱讀。 |
| 藍圖／月報 | 工程量能與月度關鍵結果缺少統一的視覺量表。 |

修改前的 10 張基準畫面保存在 `artifacts/screenshots/ui-visualization/before/`。

## 實作成果

| 區域 | 實作內容 | 精確值 |
| --- | --- | --- |
| 頂部 HUD | 日期、資金、人口、滿意、民怨、信任、評分、城市等級加入圖示與微型量表。民怨採反向健康語意。 | 保留 |
| 快捷操作 | 5 個全域操作鍵維持圖示加短標籤；建築五功能改為點擊建築後才顯示。 | 不適用 |
| 城市服務 | 治安、環境、交通、教育、醫療顯示數值、良好／留意／危險狀態與綠／金／紅量表。 | 保留 |
| 群體滿意 | 各群體加入愛心、狀態與語意色量表。 | 保留 |
| 即時財政 | 稅收、商業、工業、公用事業、交通服務、預估淨收支改為六列比例量表。 | 保留 |
| 稅率與費率 | 顯示收入方向、基準、設施缺口與低／建議／高狀態點。 | 保留 |
| 建築與政策 | 卡片使用類別圖示、成本、時鐘與 ▲／▼ 效果方向符號。 | 保留 |
| 藍圖與司法摘要 | 工程量能、委員席次、民怨與信任加入量表；未選取建築時不顯示無值的耐久量表。 | 保留 |
| 月度報告 | 淨額、人口、滿意、評分改為四張 KPI 卡與量表。 | 保留 |

視覺語言與門檻定義位於 `ux/specifications/數據視覺化UI規格.md`。

## 截圖驗證

自動截圖腳本 `tests/ui/capture_ui_readability.gd` 已加入資料視覺化規則，並於 2026-07-22 通過：

| 畫面 | 規則／實際結果 |
| --- | --- |
| 主畫面 | 8 個頂部微型量表；5 個近方形全域快捷按鈕；建築五功能情境面板與地圖皆在 1280 × 800 邊界內。 |
| 城市數據 | 15 個可見量表，超過最低 12 個。 |
| 財政 | 9 個可見量表，且費率具有狀態點。 |
| 月報 | 4 個 KPI 量表。 |
| 藍圖／深色藍圖 | 5 個當前有效量表；亮暗模式均完成擷取。 |
| 建築／政策 | 卡片包含方向效果符號。 |
| 離開確認 | 對話框與按鈕均在可視邊界內。 |

修改後的 10 張驗證畫面保存在 `artifacts/screenshots/ui-visualization/after/`；六個主要比較畫面的 SHA-256 均已改變，確認不是重複沿用基準圖片。

## 人工目視結論

逐頁檢查主畫面、城市數據、財政、政策、建築、月報、藍圖及深色藍圖後，未發現文字超出卡片、主要操作被遮擋或亮暗模式對比不足。UI 已由「讀取句子」轉為「先看圖示／方向／色彩，再讀精確數值」的資訊層級。
