# 建築選擇與藍圖設計 UX 驗收報告

日期：2026-07-22

## 改版結果

- 建築選擇由 10 個連續文字區段改為 6 個圖像分類：居住、經濟、生活服務、安全交通、基礎設施、市政。
- 每次只顯示一個分類，卡片保留名稱、價格、兩個主要效果及維護費；完整說明移至提示文字。
- 選取建築後可直接按「設計藍圖」，不必返回市政中心再尋找功能。
- 藍圖的材質、規模、樓層、人力、裝飾改為五張圖像卡，首屏同時顯示送審按鈕與案件狀態。
- 送審後立即在同頁顯示「已收件」、剩餘遊戲日與換算後的現實分鐘；按鈕改為「審核中」並停用，避免玩家誤以為沒有反應或重複送件。
- 審核通過、駁回、施工中與完工均有獨立狀態文案；資料層同步阻止審核中、已核准待開工與施工中的重複藍圖。

## 實際遊玩紀錄

測試路徑：市政中心 → 選擇建築 → 經濟 → 商店 → 設計藍圖 → 設定五項參數 → 送審 → 關閉市政畫面 → 推進日期 → 空地開工 → 完工。

| 指標 | 實測結果 |
| --- | ---: |
| 導航與主要動作 | 8 次 |
| 五項藍圖參數操作 | 5 次 |
| 不含等待時間的必要操作 | 13 次 |
| 藍圖審查 | 2 個遊戲日 |
| 商店施工 | 5 個遊戲日 |
| 建築分類捲動 | 0 次 |
| 藍圖參數捲動 | 0 次 |
| 最終結果 | 商店於地圖第 0 格完工 |

## 已確認事項與剩餘限制

- 亮色與暗色藍圖頁均已通過全螢幕截圖驗收。
- 審核中畫面已於實體 2880 × 1800、邏輯 1280 × 800 驗證；收件、5 日倒數與約 10 分鐘提示均完整可見。
- 完整流程使用實際按鈕訊號操作，沒有直接呼叫送審或開工資料函式。
- 目前同分類的個別建築共用分類插圖；若未來要再提升辨識速度，可為 23 種建築製作獨立縮圖，但不是本次流程清晰度的阻斷問題。
