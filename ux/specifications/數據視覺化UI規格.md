# 數據視覺化 UI 規格

## 目標

讓玩家先用圖形辨識狀態，再用數字確認精確值。任何視覺化不得取代原始數字，避免玩家只能估讀。

## 視覺語言

| 資訊 | 圖示 | 主色 | 視覺元件 |
| --- | --- | --- | --- |
| 日期／時間 | `◷` | 淺藍 | 日期籤、審核天數 |
| 公庫／收入 | `$`、`▲` | 綠色 | 金額卡、收入占比條 |
| 支出／風險 | `▼`、`!` | 紅橘 | 支出卡、警示條 |
| 人口 | `人` | 天藍 | 人口卡、入住數 |
| 滿意／信任 | `♥`、`◆` | 綠／金 | 0–100 狀態條 |
| 民怨 | `!` | 紅橘 | 反向 0–100 警戒條 |
| 城市評分 | `★`、`◈` | 金色 | 分數卡、城市等級 |
| 治安／環境／交通／教育／醫療 | `安`、`環`、`交`、`教`、`醫` | 依狀態 | 圖示標籤加 0–100 長條 |
| 議會／司法 | `議`、`法`、`監` | 藍／紫 | 席次比例條、案件計數籤 |

## 狀態門檻

- 75–100：良好，綠色。
- 50–74：留意，金色。
- 0–49：危險，紅橘色。
- 民怨為反向指標：0–29 良好、30–69 留意、70–100 危險。
- 收支以正負號、方向箭頭及綠／紅色同時編碼，不只依賴色彩。

## 頁面策略

- 主畫面：頂端八項核心數據改為「圖示＋數字＋微型比例條」，維持低高度，不遮擋遊戲中心。
- 城市數據：服務指標與族群滿意度均使用彩色比例條；財政以收入構成條及淨收支狀態卡呈現。
- 稅費頁：滑桿保留精確輸入，旁邊加上低／建議／高狀態籤；財政總覽改為收入、支出與淨額的比較條。
- 政策頁：卡片顯示領域圖示、影響級別、審核時間與正負效果箭頭。
- 建築頁：卡片顯示成本、維護與主要效果圖示，不再只用描述句。
- 藍圖／治理：工程隊、耐久、委員席次與警戒值使用比例條或狀態籤。
- 司法監察：以席次比例、任期、案件計數卡和委員資訊籤取代長篇連續文字。
- 月報：保留完整敘述，同時提供本月收支、人口、滿意度與城市指標摘要卡。

## 驗收

1. 修改前與修改後以同一 1280×800 邏輯尺寸、同一組 10 個畫面擷取。
2. 主畫面中央與下方主要地圖區不可因視覺化而增加遮擋。
3. 任何 0–100 指標需同時有數字、狀態詞與比例圖形。
4. 收入與支出需可在三秒內由顏色、方向與長度分辨。
5. 政策與建築卡需至少提供一個領域圖示與一組正負效果符號。
6. 深色模式、視窗範圍、主場景整合及既有系統測試必須通過。
